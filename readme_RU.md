# MCP Server - Интеграция Jira и Git

## Обзор

Этот проект представляет собой MCP (Model Context Protocol) сервер, который интегрируется с Jira и Git для автоматизации рабочих процессов разработки. Он отслеживает изменения файлов в указанном Git-репозитории, проверяет текущую ветку на наличие ключа задачи Jira и обновляет статус соответствующей задачи Jira.

Дополнительно сервер предоставляет инструменты MCP для:
* Получения деталей задачи Jira (`getJiraIssue`).
* Создания Git-ветки и шаблона Pull Request из задачи Jira (`createGitBranchAndPR`).
* Ручного обновления статуса задачи Jira (`updateJiraStatus`).

## Возможности

* **Автоматическое обновление статусов Jira**: Отслеживает изменения файлов и обновляет связанные задачи Jira (например, до статуса "В процессе"), когда обнаруживаются изменения кода в ветке функционала.
* **Интеграция с инструментами MCP**: Предоставляет инструменты, вызываемые MCP-клиентами (такими как AI-агенты или расширения IDE) для взаимодействия с Jira и Git.
* **Настраиваемость**: Использует переменные окружения для учетных данных Jira/Git и настройки поведения.

## Установка

1. **Клонирование репозитория:**
   ```bash
   git clone <url-репозитория>
   cd mcp-server 
   ```
2. **Установка зависимостей:**
   ```bash
   npm install
   ```
3. **Настройка переменных окружения:**
   Создайте файл `.env` в корне проекта, скопировав `.env.example`:
   ```bash
   cp .env.example .env
   ```
   
   Затем отредактируйте файл `.env` со своими настройками:
   ```bash
   # Конфигурация Jira
   JIRA_BASE_URL=https://<ваш-домен>.atlassian.net # URL вашего инстанса Jira
   JIRA_EMAIL=<ваш-email-jira>
   JIRA_API_TOKEN=<ваш-api-токен-jira> # Сгенерируйте в настройках учетной записи Jira > Безопасность > API-токен
   JIRA_PROJECT_KEY=<КЛЮЧ_ВАШЕГО_ПРОЕКТА> # например, PROJ
   JIRA_UPDATE_STATUS="В процессе" # Целевой статус для автоматических обновлений
   
   # Конфигурация Git
   GIT_REPO_PATH=/путь/к/вашему/локальному/репозиторию # Абсолютный путь к отслеживаемому Git-репозиторию
   GIT_DEFAULT_BRANCH=main # Или ваша ветка по умолчанию (например, develop)
   
   # Дополнительная конфигурация отладки
   # DEBUG=1 # Раскомментируйте для включения режима отладки
   # LOG_LEVEL=info # Варианты: debug, info, warn, error
   ```
   * Замените заполнители своими реальными учетными данными Jira, ключом проекта, желаемым статусом, путем к Git-репозиторию и веткой по умолчанию.
   * Чтобы сгенерировать API-токен Jira, перейдите в [Настройки учетной записи Atlassian](https://id.atlassian.com/manage-profile/security/api-tokens) > Безопасность > Создание и управление API-токенами.

## Запуск сервера

* **Разработка (с автоматическим перезапуском при изменениях):**
  ```bash
  npm run dev
  ```
* **Продакшн (сначала сборка):**
  ```bash
  npm run build
  npm start
  ```

Сервер запустится и подключится через STDIN/STDOUT для MCP-коммуникации.

## Использование (MCP-клиент)

MCP-клиент может подключиться к этому серверу (через STDIN/STDOUT при запуске) и вызвать следующие инструменты:

* **`getJiraIssue`**: 
  * Ввод: `{ "issueId": "PROJ-123" }`
  * Вывод: JSON-строка с деталями задачи Jira.
* **`createGitBranchAndPR`**:
  * Ввод: `{ "issueId": "PROJ-123" }`
  * Вывод: JSON-строка `{ "branchName": "feature/PROJ-123-summary", "prTemplate": "..." }`
  * Побочные эффекты: Создает Git-ветку, записывает `.github/PULL_REQUEST_TEMPLATE.md`, обновляет статус Jira до `JIRA_UPDATE_STATUS`.
* **`updateJiraStatus`**:
  * Ввод: `{ "issueId": "PROJ-123", "status": "Выполнено" }`
  * Вывод: Сообщение с подтверждением.
  * Побочные эффекты: Обновляет статус задачи Jira.

## Поведение отслеживания файлов

Когда сервер работает (`npm start` или `npm run dev`):

1. Он отслеживает директорию, указанную в `GIT_REPO_PATH`, на предмет изменений файлов (игнорируя `.git`, `node_modules`, `dist`).
2. При обнаружении изменения (`add`, `change`, `unlink`):
   * Проверяет название *текущей* ветки репозитория.
   * Извлекает ключ задачи Jira (например, `PROJ-123`) из названия ветки (ожидаемый формат: `тип/КЛЮЧ-123-описание`).
   * Проверяет наличие незафиксированных Git-изменений (`git status`).
   * Если найден ключ задачи И есть Git-изменения, пытается обновить статус соответствующей задачи Jira до значения, определенного в переменной окружения `JIRA_UPDATE_STATUS`.

## Переменные окружения

* `JIRA_BASE_URL`: Базовый URL вашего инстанса Jira.
* `JIRA_EMAIL`: Email, связанный с вашей учетной записью Jira.
* `JIRA_API_TOKEN`: Ваш API-токен Jira.
* `JIRA_PROJECT_KEY`: Ключ проекта для вашего проекта Jira.
* `JIRA_UPDATE_STATUS`: Название целевого статуса в Jira, который будет установлен при обнаружении изменений файлов (например, "В процессе", "Разработка").
* `GIT_REPO_PATH`: Абсолютный путь к локальному Git-репозиторию для отслеживания.
* `GIT_DEFAULT_BRANCH`: Ветка по умолчанию репозитория (например, `main`, `master`, `develop`).
* `DEBUG`: Установите значение `1` для включения режима отладки (опционально).
* `LOG_LEVEL`: Установите уровень логирования - `debug`, `info`, `warn`, `error` (опционально, по умолчанию `info`).
