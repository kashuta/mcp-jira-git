# MCP Server - Учебное руководство по интеграции Jira и Git

Это руководство проведет вас через процесс настройки и использования MCP Server для интеграции Jira и Git, что позволит автоматизировать рабочий процесс разработки.

## Предварительные требования

Перед началом убедитесь, что у вас есть:

- Установленный [Node.js](https://nodejs.org/) (версии 14 или новее)
- Учетная запись Jira с API-токеном
- Git-репозиторий, который вы хотите отслеживать
- Базовое знакомство с терминалом/командной строкой

## Шаг 1: Установка

1. Клонируйте репозиторий:
   ```bash
   git clone <url-репозитория>
   cd mcp-server
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

## Шаг 2: Настройка

1. Создайте конфигурацию окружения:
   ```bash
   cp .env.example .env
   ```

2. Откройте файл `.env` в вашем любимом редакторе и заполните значения:
   ```
   # Конфигурация Jira
   JIRA_BASE_URL=https://your-domain.atlassian.net
   JIRA_EMAIL=your-email@example.com
   JIRA_API_TOKEN=your-jira-api-token
   JIRA_PROJECT_KEY=PROJ
   JIRA_UPDATE_STATUS="В процессе"
   
   # Конфигурация Git
   GIT_REPO_PATH=/абсолютный/путь/к/вашему/репозиторию
   GIT_DEFAULT_BRANCH=main
   ```

3. Получите свой API-токен Jira:
   - Перейдите в [Настройки учетной записи Atlassian](https://id.atlassian.net/manage-profile/security/api-tokens)
   - Нажмите "Создать API-токен"
   - Дайте ему название (например, "MCP Server")
   - Скопируйте токен в ваш файл `.env`

## Шаг 3: Запуск сервера

Запустите сервер в режиме разработки (с автоматической перезагрузкой):
```bash
npm run dev
```

Или соберите и запустите в режиме продакшн:
```bash
npm run build
npm start
```

Сервер подключится через STDIN/STDOUT для MCP-коммуникации.

## Шаг 4: Использование инструментов MCP

После запуска сервера вы можете использовать его с MCP-клиентом. Ниже приведены примеры доступных инструментов:

### Получение деталей задачи Jira

```json
// Ввод
{
  "tool": "getJiraIssue",
  "input": { "issueId": "PROJ-123" }
}

// Вывод
{
  "id": "10001",
  "key": "PROJ-123",
  "summary": "Реализовать функцию X",
  "description": "Как пользователь, я хочу...",
  "status": "К выполнению"
}
```

### Создание ветки Git и шаблона PR

```json
// Ввод
{
  "tool": "createGitBranchAndPR",
  "input": { "issueId": "PROJ-123" }
}

// Вывод
{
  "branchName": "feature/PROJ-123-realizovat-funktsiyu-x",
  "prTemplate": "# Реализовать функцию X\n\n## Описание\nКак пользователь, я хочу...\n\n## Связанные задачи\n- [PROJ-123](https://your-domain.atlassian.net/browse/PROJ-123)\n\n## Чек-лист\n- [ ] Код соответствует стандартам\n- [ ] Написаны тесты\n- [ ] Обновлена документация\n"
}
```

### Обновление статуса задачи Jira

```json
// Ввод
{
  "tool": "updateJiraStatus",
  "input": { "issueId": "PROJ-123", "status": "Выполнено" }
}

// Вывод
{
  "message": "Успешно обновлен статус для PROJ-123 на Выполнено"
}
```

## Шаг 5: Настройка автоматического отслеживания файлов

Автоматическое отслеживание файлов включено по умолчанию при запуске сервера. Оно будет:

1. Отслеживать Git-репозиторий, указанный в `GIT_REPO_PATH`
2. При обнаружении изменений файлов проверять название текущей ветки на наличие ключа задачи Jira
3. Если ветка соответствует формату `тип/PROJ-123-описание` и есть незафиксированные изменения, обновлять статус задачи до значения в `JIRA_UPDATE_STATUS`

Чтобы проверить работу:
1. Убедитесь, что вы находитесь в ветке, названной по шаблону (например, `feature/PROJ-123-implement-feature`)
2. Внесите изменение в файл в репозитории
3. Проверьте логи сервера - вы должны увидеть сообщение о том, что статус задачи Jira был обновлен

## Шаг 6: Интеграция с Cursor или другими MCP-клиентами

Для подключения к этому серверу из Cursor:

1. Установите Cursor AI с сайта [cursor.sh](https://cursor.sh)
2. Настройте подключение MCP Server в настройках Cursor
3. Укажите на запущенный процесс MCP Server
4. В Cursor вы теперь можете взаимодействовать с MCP Server, используя команды вроде:
   - "Получить детали задачи Jira PROJ-123"
   - "Создать ветку для задачи PROJ-123"
   - "Обновить статус PROJ-123 на Выполнено"

## Устранение неполадок

### Распространенные проблемы

1. **Невозможно подключиться к API Jira**
   - Проверьте ваши учетные данные Jira в `.env`
   - Убедитесь, что ваш API-токен имеет необходимые разрешения
   - Проверьте правильность вашего домена Jira

2. **Сбои операций Git**
   - Убедитесь, что `GIT_REPO_PATH` корректный и абсолютный
   - Проверьте, что у вас правильно настроены учетные данные Git
   - Убедитесь, что ветка `GIT_DEFAULT_BRANCH` существует

3. **Отслеживание файлов не обновляет статус Jira**
   - Проверьте, соответствует ли название вашей ветки ожидаемому формату
   - Убедитесь, что действительно есть незафиксированные изменения в Git
   - Проверьте, существует ли целевой статус из `JIRA_UPDATE_STATUS` в вашем рабочем процессе Jira

### Логи и отладка

Включите режим отладки, установив в вашем `.env`:
```
DEBUG=1
LOG_LEVEL=debug
```

Это обеспечит более подробное логирование для помощи в диагностике проблем.

## Расширенное использование

### Настраиваемые рабочие процессы статусов

Вы можете настроить автоматические обновления статусов, изменив переменную `JIRA_UPDATE_STATUS`. Убедитесь, что название статуса существует в рабочем процессе вашего проекта Jira.

### Использование с CI/CD

Вы можете использовать этот сервер в конвейере CI/CD, выполнив следующие действия:
1. Настройка переменных окружения в вашей CI/CD-системе
2. Запуск сервера в начале вашего конвейера
3. Использование инструментов MCP для автоматизации операций Git и Jira во время процесса сборки/развертывания

## Лучшие практики

1. **Безопасность**:
   - Никогда не фиксируйте ваш файл `.env` в системе контроля версий
   - Периодически меняйте ваш API-токен Jira
   - Используйте отдельную учетную запись Jira для автоматизации

2. **Рабочий процесс**:
   - Настройте соглашения по именованию веток в вашей команде для обеспечения единообразия
   - Документируйте ожидаемый формат ветки для членов команды
   - Рассмотрите возможность настройки Git-хуков для принудительного соблюдения соглашений по именованию
